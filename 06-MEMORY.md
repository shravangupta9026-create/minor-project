# Project Memory

## Product Context

SheRise AI is a client-side learning experience for women entrepreneurs. The current flow connects an entrepreneurship assessment to skill recommendations, self-paced business lessons, locally saved progress, and a lesson-context assistant.

## Important Architecture Decisions

- React Router owns navigation; shared `Navbar` renders from the root route layout.
- Assessment recommendation rules and local storage handling live in `src/utils/assessmentData.js`.
- Learning modules and lesson metadata live in `src/data/learningModules.js`.
- Learning progress calculation and local storage handling live in `src/utils/learningProgress.js`.
- The assistant is a local mock service in `src/services/aiService.js`; there is no external model/API call.
- No global state library, backend, database, account system, or deployment platform is configured.

## Important Implementation Details

- Routes are `/`, `/assessment`, `/results`, `/learning`, `/dashboard`, `/learning/module`, and `/learning/lesson`; unknown routes show `NotFound`.
- Assessment answers are stored under `sherise-assessment-answers-v1` after all five questions are answered.
- Learning data is stored under `sherise-learning-progress-v1` as an active module and completed lesson indexes keyed by module name.
- There are three learning modules—Digital Marketing, Business Strategy, and Financial Skills—with four lessons each.
- Assessment scoring returns the three highest-scoring areas from Business Strategy, Digital Marketing, Financial Skills, and Leadership & Communication. The last area has a recommendation description but no corresponding learning module.
- The lesson page contains special lesson content for Digital Marketing; other lesson bodies are generated from shared templates based on module.
- `askAI` accepts a message, lesson context, conversation history, and quiz-answer flag, then returns a local response after a 350ms delay.
- Router location state passes answers and lesson context between screens; persisted values are used as fallbacks on direct route visits.

## Do Not Break

- Keep the five-answer assessment flow connected to results and saved answers.
- Keep module names consistent between assessment recommendations, learning data, and stored progress.
- Keep lesson completion indexes valid for the module lesson list and preserve progress calculation behavior.
- Keep the assistant's lesson context and quick action flow intact unless replacing it deliberately.
- Do not move provider secrets into the browser if a real AI integration is added; use a secure server-side boundary.
- Preserve narrow-screen layout behavior, menu controls, visible focus, and accessible labels when changing shared styles.

## Known Limitations

- Answers and progress exist only in the current browser's local storage; there is no account-based sync or backend.
- Assistant responses are heuristic/local mock content and are not generated by an AI provider.
- No automated test framework or browser viewport test suite is configured.
- Google Fonts requires an external request; local fallback fonts are configured.
- Assessment may recommend Leadership & Communication, but the learning module catalog currently has no module for that skill.

## Future Decisions

- Whether to create a Leadership & Communication module or change recommendation scoring to only suggest available modules.
- Which browser automation and accessibility testing tools to adopt.
- Whether lesson content should be moved fully out of page components into the learning data layer.
